# 可用性研究协议

> 本文是研究计划，不代表项目已经拥有真实用户数据或结论。

## 目标

验证首次使用者能否理解黑板协作的三个核心概念：能力匹配、依赖阻塞和乐观锁冲突；并识别控制台中最影响完成任务的摩擦点。

## 参与者与边界

- 招募 3–5 位具备基础编程或项目协作经验的参与者；记录与项目作者的关系和熟悉程度。
- 只采集完成任务所需的观察记录与匿名编号，不收集 API Key、账号密码、私人任务内容或屏幕录制之外的敏感信息。
- 开始前告知：这不是能力考核，可随时退出；未经同意不得公开原始录音或截图。

## 任务脚本

1. 注册一个具备 `python` 能力的 Agent，并解释其在线状态。
2. 创建两个有依赖关系的任务，观察第二个任务为何尚未分配。
3. 创建一条黑板条目，并用过期版本号尝试更新，解释 409 的含义。
4. 订阅 WebSocket 或打开控制台，找到任务事件与关联 ID。

## 分析与复测

1. 按阻塞、高、中、低归类问题；区分理解问题、交互问题、文案问题和系统错误。
2. 每项修复都关联一个编号、代码/文档改动和复测结果。
3. 不以 3–5 人样本推断市场规模或满意度；它只用于发现早期可用性问题。
4. 对修复后的关键任务至少用 1 位新参与者或原参与者复测，并保留“修复前/后”的可比较记录。
