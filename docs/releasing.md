# 发布策略

## 版本规则

项目采用语义化版本：

- `MAJOR`：破坏公开 API、数据模型或规则语义的兼容性变更。
- `MINOR`：向后兼容的新 API、新规则动作或新控制台能力。
- `PATCH`：缺陷、安全和性能修复。

## 发布清单

1. 在干净工作区运行编译、Pyright、pytest、API/WebSocket/运行时冒烟。
2. 更新 `CHANGELOG.md`，记录用户可感知的变更与迁移事项。
3. 创建带注释的 Git tag，例如 `v1.1.0`。
4. 发布 GitHub Release，附上亮点、兼容性说明、升级步骤和已知限制。
5. 验证 Docker Compose 从空卷启动、健康检查和控制台访问。

## 支持策略

`main` 始终代表下一稳定版本。安全修复优先进入 `main`；如有活跃稳定分支，仅为最近一个
MINOR 版本提供关键安全修复。公开 API 废弃至少经历一个 MINOR 版本，并在 Changelog 中说明。
