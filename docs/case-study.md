# Agent Blackboard 案例说明

## 问题与目标

当多个自动化参与者共享任务状态时，常见失败不是“没有计算结果”，而是并发覆盖、依赖未完成就被执行、或冲突没有留下治理记录。Agent Blackboard 的目标是提供一个本地优先、可观察、可验证的协作参考实现：把状态、规则、冲突和实时事件放在一条可审计链路中。

## 产品规则

- 写入共享条目必须携带版本；过期版本返回冲突而非静默覆盖。
- 任务只有在依赖完成后才能进入可分配状态。
- 自动分配同时考虑能力标签、在线状态和负载，而非先到先得。
- 冲突进入终态后不能重复解决；规则更新只允许白名单字段。
- 写操作可由 API Key 保护；实时事件可通过 `trace_id` 关联到原始 HTTP 请求。

## 实现与验证

FastAPI 提供 REST/WebSocket 边界，Pydantic 约束输入，aiosqlite 存储状态，事件总线驱动规则执行和实时推送。测试覆盖领域服务、回归、API、WebSocket、运行时边界和性能脚本；CI 执行编译、类型检查、pytest 与集成冒烟。

## 已知边界

- 项目是单实例本地优先参考实现，SQLite 的单写入者特性不等于生产多副本容量。
- 当前“Agent”是确定性协作角色，不是 LLM 自主规划器；详见 [Agent 与 Workflow 的边界](agent-vs-workflow.md)。
- 当前没有真实用户研究结论。可用性研究应按 [研究协议](usability-study.md) 真实执行并记录。
- 性能数据必须与机器环境一起解释；详见 [性能基线与报告](benchmarking.md)。
